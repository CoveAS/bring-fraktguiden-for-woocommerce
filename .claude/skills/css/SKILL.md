# CSS & Styling Guide

## Overview

This plugin uses a multi-layered styling approach:
- **Tailwind CSS** with `bfgu:` prefix for utility classes
- **BFG Component System** (`.bfgc.php` templates) for reusable UI components
- **Custom CSS** for complex component styling and legacy features

## Quick Decision Tree

1. **Simple layout/spacing?** → Use Tailwind utilities with `bfgu:` prefix
2. **Reusable UI pattern?** → Use or create a BFG component (see `/use-component` or `/create-component` skills)
3. **Complex styling for a specific component?** → Write custom CSS with `bfg-` prefix using BEM notation in the relevant partial under `resources/css/admin/`

## Tailwind Utilities (Preferred for Layouts)

Use Tailwind utility classes with the `bfgu:` prefix for layouts, spacing, and simple styling:

```php
<div class="bfgu:flex bfgu:flex-row bfgu:gap-4">
    <div class="bfgu:flex-1">
        <!-- Content -->
    </div>
    <div class="bfgu:flex-1">
        <!-- Content -->
    </div>
</div>
```

**When to use:**
- Flexbox/grid layouts
- Spacing (padding, margin, gap)
- Simple colors, borders, shadows
- Responsive design
- Any standard Tailwind utility

**Compiled output:** `build/css/admin.css` (generated by Tailwind -- never edit directly)

## CSS Source File Structure

`resources/css/tailwind.css` is the entry point. It imports Tailwind and then all admin partials in load order:

```
resources/css/
  tailwind.css              ← entry point (imports only, do not add styles here)
  admin/
    _tokens.css             ← CSS custom properties (colors, typography, spacing, button vars)
    _layout.css             ← page skeleton, .bfg-admin-page, section/header structure
    _buttons.css            ← button variants (.bfg-btn-*)
    _forms.css              ← form fields, labels, inputs
    _checkboxes.css         ← checkbox styling
    _steps.css              ← onboarding step components
    _badges.css             ← badge variants
    _notices.css            ← notice/alert components
    _custom-select.css      ← custom dropdown select
    _pro-teaser.css         ← Pro upsell teaser blocks
    _pro-page.css           ← Pro license/subscription page
    _home.css               ← Get Started / home page
    _responsive.css         ← media queries (import last among components)
    _toggle-legacy.css      ← legacy toggle styles (keep, do not rewrite)
    _booking-legacy.css     ← legacy booking styles (keep, do not rewrite)
```

**Load order matters:** tokens must come first (everything else references their variables). Legacy files come last.

### Where to add new styles

- **New design token (color, radius, shadow)?** → `_tokens.css`
- **New button variant?** → `_buttons.css`
- **Form field styling?** → `_forms.css`
- **New component type not covered above?** → Create `_my-component.css` and add its `@import` to `tailwind.css` before `_responsive.css`
- **Responsive overrides for an existing partial?** → `_responsive.css`
- **Do not** add component styles directly to `tailwind.css` — it is imports only

### Styling BFG Components

Component styles live in the relevant partial, using BEM notation with the `bfg-` prefix:

```css
/* In resources/css/admin/_layout.css (or the matching partial) */
.bfg-section {
    background: var(--bfg-bg-card);
    border: 1px solid var(--bfg-border);
    border-radius: var(--bfg-radius-card);
}

.bfg-section__header {
    padding: 0;
    margin-bottom: 32px;
}
```

**To modify component styles:**
1. Edit the appropriate partial in `resources/css/admin/`
2. Run `npm run build` (or `npm run watch`) to compile to `build/css/admin.css`
3. Component HTML templates are in `src/components/*.bfgc.php`

## Other CSS Files

- **Frontend** (cart/checkout): `assets/css/bring-fraktguiden.css` (legacy styles only)
- **Pro Admin**: `pro/assets/css/admin.css` (Pro-specific features)
- **Shipping services frontend**: `resources/css/shipping-services.css`

Do not edit `build/css/admin.css` directly -- it is generated output.

## Custom CSS Best Practices

### Class Naming Convention

- **Utility classes**: `bfgu:` prefix (Tailwind only -- don't create custom utilities)
- **Component classes**: `bfg-` prefix with BEM notation

### BEM Notation

Use BEM (Block, Element, Modifier) for component classes:

```css
/* Block */
.bfg-custom-select {
    position: relative;
    width: 100%;
}

/* Element (only when necessary) */
.bfg-custom-select__dropdown {
    position: absolute;
}

/* Modifier */
.bfg-custom-select--disabled {
    opacity: 0.5;
}
```

**Tip:** Avoid using "Element" unless there's a clear hierarchical relationship.

### Avoiding !important

Avoid `!important` unless necessary. When you must use it, document the reason inline:

```css
.bfg-custom-select {
    width: 100% !important; /* override WooCommerce .form-field width */
    max-width: none !important; /* override WordPress .button max-width */
}
```

### When to Create Custom Component Classes

Consider creating a component class when:
- An element uses 4+ utility classes repeatedly
- The styling represents a distinct UI pattern
- You need hover/focus states or pseudo-elements
- The pattern isn't covered by existing BFG components

**Example:**
```html
<!-- Before: Too many utilities -->
<button class="bfgu:bg-blue-500 bfgu:text-white bfgu:px-4 bfgu:py-2 bfgu:rounded bfgu:hover:bg-blue-600">
    Click me
</button>

<!-- After: Component class -->
<button class="bfg-primary-button">Click me</button>
```

```css
/* In resources/css/admin/_buttons.css */
.bfg-primary-button {
    background-color: #3b82f6;
    color: white;
    padding: 0.5rem 1rem;
    border-radius: 0.25rem;
}
.bfg-primary-button:hover {
    background-color: #2563eb;
}
```

## Migration Notes

- Old utility prefix `bfgu-` → Use Tailwind `bfgu:` instead
- Styles that were in a single `tailwind.css` are now split into partials under `resources/css/admin/`
- Complex HTML patterns → Consider creating a BFG component
- Repeated styling → Check if a BFG component already exists
